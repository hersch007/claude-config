**Decision (Richard, 2026-07-10):** the AI Assistant should not be a separate nav entity. AI is a *cross-cutting capability*, not a place users go. Reasoning: its value lives in-context (contact summaries via `sp_contact_edit_after`, ticket triage via `sp_ticket_edit_after`, ticket-list analysis via `sp_tickets_after_list`, Pipeline Insights), and its only config is an API key. A standalone "AI Assistant" landing page was thin and competed for top-level nav space with substantial modules. He first asked whether to fold it into Knowledge Core — **no**: Knowledge is a content library with its own tables; AI is infrastructure other modules consume. Merging would also destroy the per-site on/off switch (AI is deliberately **inactive on SMTI**).

**What was done (core 2.5.13, ai 1.3.4, intelligence 1.2.3):**
1. Removed the two AI cards from the **core dashboard** (`start-performance/templates/views/dashboard.php`): the hardcoded "AI Business Summary" block (was core reaching into an addon — the real violation) and, from the AI plugin, the `sp_dashboard_after_grid` Pipeline Insights hook. Nothing lost — Intelligence Core already renders its own "AI Smart Summary".
2. Removed the AI plugin's standalone nav item + `ai` view (`sp_register_view('ai',...)`, the `sp_nav_items`/`sp_allowed_views` filters, and the `sp_ai_nav_items`/`sp_ai_allowed_views` functions). `templates/views/ai.php` left on disk but unreachable.
3. Repointed the addon's `settings_url` to `?view=settings#section-ai`. Config already lived there (`sp_ai_settings_tab`, `sp_ai_settings_section`).
4. Relocated **Pipeline Insights** to Intelligence Core via a new action `sp_intel_after_ai_summary` (fires right under the AI Smart Summary card in `intelligence.php`). AI plugin hooks it: `add_action('sp_intel_after_ai_summary','sp_ai_pipeline_insights_ui')`. Safe because on both AI-active sites (sp, fruth) Intelligence Core is also active. See [[core_platform_architecture]].

**THE GOTCHA — core-slot "locked upsell teaser":** removing the nav item was NOT enough. Core has a *core-slot* system (`sp_register_core_slot`, e.g. `ai-core`, `chat-core`) rendered as sidebar sections. In `templates/app.php` (~line 69-100), a two-pass loop: pass 1 records which `section_id`s have a visible nav item; pass 2 injects a **locked upsell teaser** (`'view'=>'sp-core-upsell'`, `'locked'=>true`, class `sp-nav-item-locked`) after any section header whose slot has NO items. So deleting the AI nav item made "AI Assistant" reappear as a *greyed-out, italic, locked "buy this" teaser* — as if AI weren't installed, even though it was active. Worse than before.
- **Fix:** the AI addon, when active, strips its own core-slot section entirely — `add_filter('sp_nav_items','sp_ai_hide_nav_section',50)` removes the `section_id === 'ai-core'` section header. No header → pass 2 injects no teaser. On installs *without* the AI addon the teaser correctly remains (that's the intended marketing prompt). Verified live: nav has zero "AI Assistant"; only remaining locked teaser is "Chat Core" (no chat addon exists — correct).
- **General rule:** if you remove an addon's only nav item but the addon stays active, also suppress its `*-core` slot section, or core will show a misleading locked upsell in its place. The core-slot definition stays intact so AI is still marketed as a sellable core on the Add-ons page for prospects.

**Reaffirmed 2026-07-10:** during a later nav-reorg, Richard was explicitly offered the option to give AI a home by folding it into Intelligence Core (relabel / sub-entry) vs. leaving it out of the nav entirely. He chose **leave it out** — "AI is infrastructure, not a place." So the no-nav-entry state is deliberate and settled; do not re-add an AI nav item or section without a new explicit request.

**`ai-core` slot fully removed (core 2.5.18, 2026-07-10):** the earlier fix (addon strips its own `ai-core` section when active) left a hole — on SMTI, where the AI addon is **inactive**, the `ai-core` core-slot still rendered "AI Assistant" as a dimmed **locked upsell teaser** (`view=sp-core-upsell`), i.e. AI reappeared in the menu wherever it was off. Richard chose to remove it entirely. Deleted: the `sp_register_core_slot('ai-core', …)` registration (`start-performance.php`), the hardcoded `ai-core` section header in `templates/app.php`, and the three `ai-core` refs in `templates/views/settings.php` (nav-visibility list, section-label rename map, `$core_section_ids`). Net effect: AI never appears in the nav OR the Add-ons upsell on any site, active or not — AI is no longer a "sellable core." It stays fully functional (Settings → AI, in-context, Intelligence). NOTE: the AI addon still has a now-redundant `sp_ai_hide_nav_section` filter (harmless no-op since core no longer emits an `ai-core` section) — left in place to avoid re-deploying the addon.

**Deploy note:** AI addon is force-activated by `deploy.ps1` — but it must stay **inactive on SMTI**. Deployed via `deploy.ps1` to sp+fruth only; SMTI updated manually with `wp plugin install <zip> --force` (NO `--activate`). See [[feedback_custom_module_deactivation]].
