# FiberCo — 5th SP instance (started 2026-07-14)

FiberCo is a **fiber-internet ISP lead-gen demo** brought into Start Performance as a new instance, the same way [[project_wts_lms]] wrapped WTS. Richard's decisions: **new SP instance** (not a demo module on sp), and **wrap FiberCo's own chatbot as-is** now, unify with the platform [[project_chat_core]] later.

## Two source assets (from the OLD standalone site)
1. **Quote Wizard** — a public `[fiberco_quote]` shortcode (WPCode/IHAF snippet): address → plan → info → payment → confirm funnel for residential + business fiber plans. Client-side/demo (no order persistence). Blue **#0057FF**, "Plus Jakarta Sans". Exposes `window.fibercoQuoteStartFromChat()` so the chatbot can prefill/drive it.
2. **FiberCo AI Chatbot** plugin (v1.3.4) — the real engine. **Claude/Anthropic-powered** (`api.anthropic.com`, key in option `fiberco_ai_api_key`, NOT hardcoded). Creates table `fiberco_chat_logs` (id, session_id, ip_address, user_message, bot_response, escalated, created_at). Has its own wp-admin dashboard + a PIN-protected front-end dashboard (`fiberco_dashboard_pin`) + CSV export. Logs each visitor-msg→bot-reply exchange; "escalated" = handed to a human.

## `fiberco-sp` addon (NEW, 0.1.0) — the SP integration
Lives in the platform `plugin/fiberco-sp/` tree (built by `build.ps1`, deploy key **`fiberco-sp`** sites=`@("fiber")`). Mirrors the Fruth `sales-quote-system` SP-integration pattern:
- `sp_register_addon('fiberco-leads', core_slot=>'sales-core')` — so **Sales Core is active/owned by FiberCo** (built-in sales is off).
- `sp_register_view('fiberco-leads', templates/fiberco-leads.php)` + `sp_nav_items` inserts **"FiberCo Leads"** right after the sales-core header; `sp_allowed_views` whitelists it.
- Dashboard + Intelligence providers read `wphu_fiberco_chat_logs`: `sp_dashboard_before_stats` (Conversations + Escalations cards), `sp_intel_kpi_cards`, `sp_intel_summary_lines`.
- The **view** = searchable table (date/session, visitor message, bot reply, escalated badge) + 4 KPI cards (Conversations, Total Messages, Escalations, This Week) + **CSV export** via an `init` handler `?fiberco_sp_export=1` gated on `sp_is_authed()`.
- Helper `fiberco_sp_lead_stats()` (static-cached): messages, distinct-session conversations, escalations, this-week.

## Address validation LOOSENED (2026-07-15, fiberco-quote 4.23 + chatbot 1.3.5)
Richard: address step "fails a lot" when input isn't perfectly formatted. Both surfaces demanded street# + 5-digit ZIP (+ state in chat) — but **availability is a demo that always returns "available"**, so strict validation was pure friction. Chose "loosen now" (over Google Places autocomplete, which would need a Maps API key). Changes: **funnel** `fcqCheckAddress` + the chat-bridge `hasFullAddr` now just `length>=4 && /[a-z]/` (accepts "123 Main St", "Springfield IL", "Rock Hill SC 29730", etc.; rejects "hi"/"123"); softened the error copy. **Chatbot** `fiberco_is_usable_address` accepts a street#, OR a ZIP, OR "word word" street/city text; `fiberco_extract_possible_address` no longer requires a street suffix (St/Rd/Ave) and adds a bare-ZIP fallback. Verified live end-to-end: full funnel completed with "123 Main St" (no ZIP) → order confirmed; SP Leads dashboard live-updates (chat tests grew it to 7 convos/18 msgs). Google Places autocomplete remains the future "premium" upgrade if wanted.

GOTCHA that ate 3 deploys: `#fc-messages` has `scroll-behavior:smooth`, and `el.offsetTop` is unreliable (container is `position:static`). Working formula = `setTimeout(60)` → temporarily set `messages.style.scrollBehavior='auto'` → `messages.scrollTop += (el.getBoundingClientRect().top - messages.getBoundingClientRect().top) - 12`. `scrollTo({behavior:'auto'})` does NOT mean instant (it means "use CSS behavior"=smooth) and silently no-ops — use direct scrollTop with behavior forced to auto.
