**The "Here's what needs your attention today" email is the SP core daily digest.** Cron hook `sp_daily_digest` (in `start-performance/start-performance.php`) runs daily at 8:00 AM site time → `sp_send_daily_digest()` emails every active team member (`sp_team` status=active, non-empty email) a summary of their OVERDUE tasks, DUE TODAY tasks, and note reminders (`sp_notes.reminder_at` ≤ now, reminder_sent=0). Members with nothing pending get no email (the loop `continue`s). Tasks are matched by `assigned_to`. **Subject** (core 2.5.6): `Daily Digest from {sp_platform_name}` (was "Your reminders — {date}"); footer also uses `sp_platform_name` (white-label fix). **HTML email (core 2.5.7):** now sends branded HTML via helper `sp_digest_email_html($name, $sections)` (table + inline-style layout, email-client-safe) with `wp_mail(..., array('Content-Type: text/html; charset=UTF-8'))`. Auto-brands per site from `sp_platform_name` + `sp_accent_color` (header accent rule, CTA button, links) + logo from `sp_brand_icon_url`||`sp_logo_url`. Dark `#0f172a` header with the logo on a WHITE chip (core 2.5.8 — so black/dark logos like SMTI's "Sport Medical Vertical Black" stay visible; height fixed 26px + width auto so non-square logos aren't distorted). All 3 sites already have brand_icon/logo URLs set (SP=START favicon, SMTI=Sport Medical black PNG on HubSpot, Fruth=fruth-icon/wordmark) so the email auto-shows each real logo, no config needed. Color-coded sections (Overdue #b91c1c/#fee2e2, Due Today #b45309/#fef3c7, Note Reminders #4f46e5/#e0e7ff), each item links to its record (`?view={type}s&action=view&id=&tab=tasks|notes`). `sp_send_daily_digest()` builds `$sections` array then calls the helper. Test sends: `wp_mail('richard@grouprb.com', ...)` via eval-file (user's address = the Admin sp_team member's email).

**Now controllable (core 2.5.5, 2026-07-06).** Added option `sp_daily_digest_enabled` (default 1 = on, preserving prior behavior) and a super/admin checkbox **Settings → Email → "Daily reminder digest email"** (in `templates/views/settings.php` `section-email` form; saved in the `sp_type==='settings'` handler, gated on `$_POST['sp_settings_section']==='email'` because an unchecked box isn't POSTed — otherwise other settings forms would clear it). Scheduling was refactored into `sp_schedule_daily_digest()` (idempotent, 8AM site tz), shared by activation, the toggle (schedules on enable / `wp_clear_scheduled_hook` on disable), and a self-heal `add_action('init','sp_maybe_schedule_daily_digest')` that reschedules whenever enabled-but-not-scheduled. `sp_send_daily_digest()` also early-returns when the option is off (belt + suspenders). Deployed 2.5.5 to all 3; the self-heal fixed SMTI which previously had NO digest cron — now all 3 fire ~8AM. To turn off for a site: uncheck the box (or `wp cron event delete sp_daily_digest` + set option 0, but the toggle is durable and the CLI clear alone would self-heal back on).

**GOTCHA — `sp_tasks` has NO `updated_at` column.** An `UPDATE ... SET status=..., updated_at=NOW()` silently errors (`$wpdb->query` returns false). Task "done" = `status='done'` (varchar(20); values in use: open/done). To complete a task via SQL: `UPDATE {prefix}sp_tasks SET status='done' WHERE id=...` — no updated_at. (Cleaned demo duplicate tasks #14/#18 "Prepare account summary for client" assigned to Admin on sp this way; Admin now has 0 overdue.)
